# Принятые решения

Где задание допускало несколько вариантов или молчало, решение принято здесь, с причиной.

## Данные и целостность

**1. Остаток считается в `Decimal`, а не через `F()`.** Задание предлагало
`update(stock=F("stock") - qty)`. В SQLite колонка `DECIMAL` хранится как `REAL`, и арифметика `F()`
идёт в двоичной плавающей точке. Проверено на настоящей базе: приход 0,3 → выдача 0,1 → выдача 0,2
даёт −2,8·10⁻¹⁷, и `CHECK (stock >= 0)` отклоняет законную выдачу всего остатка. Поэтому новый остаток
считается в Python `Decimal` и записывается условным `UPDATE … WHERE stock = <прочитанное значение>`.
Благодаря `transaction_mode = "IMMEDIATE"` блокировка на запись берётся в момент `BEGIN`, так что
между чтением и записью никто не вклинится. `CHECK` в базе остаётся последней линией защиты. Тест
`test_no_binary_float_drift` фиксирует этот случай.

**2. SQLite: `IMMEDIATE`, `timeout=20`, WAL.** WAL позволяет читателям не ждать писателя. Тестовая база —
файл, а не общая память: только так тесты с параллельными потоками видят настоящие блокировки.

**3. Операции — журнал только для добавления.** `Operation.delete()` и `QuerySet.delete()` бросают
исключение, `product` и `created_by` защищены `PROTECT`. Отмена — отдельное событие:
`cancelled_by/cancelled_at` заполняются условным `UPDATE … WHERE cancelled_at IS NULL`, поэтому вторая
отмена (даже параллельная) получает «Операция уже отменена (кем, когда)».

**4. История — одна SQL-выборка.** Операции и отмены объединяются через `UNION ALL` и сортируются по
времени события, по 50 на страницу, с фильтрами по товару и типу. Отдельная таблица событий не нужна,
данные не дублируются.

**5. Удаление товара.** Без операций — можно (исправить опечатку). С операциями — только архив.

**6. Архив только при нулевом остатке.** Иначе часть склада исчезла бы из остатков и итогов, а выдать её
было бы нельзя. Отмена операций по архивному товару работает, как требует задание.

**7. Название товара.** Пробелы по краям обрезаются, повторные пробелы внутри схлопываются. Уникальность
среди активных товаров — без учёта регистра, включая кириллицу: SQLite `LIKE` сворачивает регистр только
для ASCII, поэтому хранится копия `name_key` (`casefold()`), на ней частичный уникальный индекс и поиск.
Название из архива можно занять заново, а вернуть такой товар из архива нельзя, пока имя занято.

**8. Единица измерения фиксируется после первой операции.** Проверка есть и в сервисе, и в форме
(поле заблокировано с пояснением).

**9. Пользователи.** Своя модель `User` с полем `role`, а не `Profile`: роль читается без лишнего
запроса. Пустая роль означает «никаких прав». Три демо-пользователя создаются data-миграцией и не
перезаписываются при повторном запуске.

**10. Django admin отключён полностью** (не установлен), чтобы через него нельзя было обойти права.

## Числа и деньги

**11. Ввод.** Принимаются запятая и точка, пробелы как разделители тысяч (`1 000,5`). Отклоняются знак,
экспонента, `NaN`/`Infinity`, ноль, не-ASCII цифры. Нули в конце не считаются знаками: `1,2340` = `1,234`.
Пределы: одна операция до 1 000 000 000, остаток до 99 999 999 999,999 (столько вмещает `Decimal(14,3)`),
цена до 10¹¹. Поле ввода текстовое, а не `type=number`: иначе часть браузеров не принимает запятую.

**12. Отображение денег.** Если сумма целая, копейки не показываются, иначе — два знака. Так
согласуются примеры из задания «340 $» и «55,60 $». Правило одно для всех валют, включая сум. Сумма
строки = `(остаток × цена).quantize(0.01, ROUND_HALF_UP)`. Итог по валюте — сумма уже округлённых строк,
поэтому он всегда совпадает с тем, что видно в таблице. Валюты не конвертируются.

**13. Количество** показывается без лишних нулей: `69,5 м`, `100 м`, `3 шт`.

## Права и приватность

**14. Цены скрыты на уровне данных.** Для кладовщика запрос остатков делается `values()` без `price`,
поэтому цены нет ни в контексте шаблона, ни в Excel. Выпадающий список товаров ни для какой роли не
содержит цену: в нём единица и остаток (`.only("id", "name", "unit", "stock")`).

**15. Матрица прав в одном месте, по умолчанию — запрет.** Анонима отправляем на вход, остальным при
отказе — 403. Тест обходит все URL из `urls.py` и падает, если у какого-то представления нет
`@role_required`.

## Двойная отправка

**16. Ключ идемпотентности** генерируется при каждом показе формы. Повтор с тем же ключом возвращает
уже сохранённую операцию («Операция уже сохранена»). Ключ чужого пользователя не принимается. При
ошибке валидации ключ сохраняется, так что исправленная форма тоже не создаст дубль. Дополнительно
кнопка блокируется скриптом и действует PRG: после сохранения — редирект на остатки, F5 ничего не
отправляет повторно.

## Безопасность

**17. `DEBUG` по умолчанию выключен.** `ALLOWED_HOSTS` по умолчанию — `localhost`, `127.0.0.1`, `[::1]`,
поэтому шаги из README работают и без `.env`. `run.bat`/`run.sh` включают `DEBUG` только для запуска на
своём компьютере. Режим `lan` (доступ с телефона) отладку не включает.

**18. CSS и JS встроены в шаблон.** Так страница выглядит одинаково и с `DEBUG=False` под
`runserver`, и в Docker — без WhiteNoise, nginx и `collectstatic`. Файлы маленькие (≈8 КБ), CDN нет.

**19. Ограничение попыток входа:** 5 неудач на пару «логин + IP» блокируют её на 5 минут после
последней неудачи (кеш Django, без библиотек). IP берётся из `REMOTE_ADDR`: `X-Forwarded-For` можно
подделать. Кеш `LocMem` живёт в одном процессе — для одного процесса достаточно, при нескольких
процессах нужен общий кеш (Redis/memcached). Ошибка всегда одна: «Неверный логин или пароль». Во
время блокировки сообщение о блокировке — оно не раскрывает, верен ли пароль.

**20. `check --deploy`.** С `DEBUG=0` остаются 4 предупреждения (W004, W008, W012, W016), все про HTTPS.
Они снимаются переменными `DJANGO_SECURE_COOKIES=1`, `DJANGO_SSL_REDIRECT=1`, `DJANGO_HSTS_SECONDS`.
По умолчанию выключены: локально и в сети по HTTP с ними нельзя было бы войти. W005 (HSTS на
поддомены) и W021 (HSTS preload) оставлены выключенными сознательно: это решение для всего домена,
и отменить его трудно.

**21.** Выход и переключение языка — только POST. Все изменения — только POST с CSRF. `next` после
входа проверяется `url_has_allowed_host_and_scheme`. `|safe` и `mark_safe` не используются — это
проверяет тест.

## Интерфейс и язык

**22. Исходные строки на русском** (язык по умолчанию), перевод только узбекский. В узбекском
используется латиница с официальными знаками ʻ (oʻ, gʻ) и ʼ, а не ASCII-апостроф: так он не
экранируется в HTML. Термины: приход — «Kirim», выдача — «Chiqim». GNU gettext в Windows обычно не
установлен, поэтому `.mo` собирает небольшая команда `compile_translations` на чистом Python, а тест
проверяет полноту перевода и актуальность `.mo`.

**23.** После прихода или выдачи — переход на остатки с сообщением «Приход сохранён: Кабель 3×1.5 — 100 м».
Отмена — через отдельную страницу подтверждения и `confirm()`.

**24. Excel:** `stock_ГГГГ-ММ-ДД.xlsx`, числа — числовые ячейки с форматом, валюта — отдельной колонкой
(код), итоги по каждой валюте внизу. У кладовщика только три колонки и нет итогов: итоги денежные.
Текст, начинающийся с `= + - @`, табуляции или перевода строки, получает префикс `'`.

## Что считается сценарием из раздела 10

Сам раздел 10 в тексте задания — это чек-лист, а сценарий восстановлен по нему: товар «Кабель 3×1.5»,
метры, 0,80 $; приход 100 м (80 $) → выдача 30,5 м (69,5 м, 55,60 $) → попытка выдать 70 м даёт
«На складе только 69,5 м» → отмена прихода запрещена (из него уже выдано 30,5 м) → отмена выдачи
возвращает 100 м. Он реализован тестом `EndToEndScenarioTests`.

## Известное ограничение

Часы Windows с Python 3.12 тикают раз в ~15,6 мс. Если два события произошли в пределах одного тика,
порядок между ними в истории определяется номером операции. Для действий людей это незаметно, а на
Linux и в Docker время микросекундное.
